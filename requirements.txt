# The offline store is explicitly DuckDB (see feature_store/feature_store.yaml), not
# Feast's default "file" offline store. The "file" store's point-in-time join does a
# pandas merge on the entity join key BEFORE filtering by timestamp; with this
# project's single constant entity (one location, "karachi"), that merge matches every
# row against every row - an O(n^2) cross product that reliably runs out of memory on
# the full multi-year hourly dataset (confirmed: OOMs above ~7k rows on a typical
# laptop). DuckDB's offline store compiles the same point-in-time join into a single
# SQL query DuckDB executes without materializing that cross product - same local,
# no-cloud, no-Docker setup, just a join engine that doesn't blow up at this project's
# scale. duckdb/ibis-framework/pyarrow_hotfix are DuckDB offline store dependencies.

ibis-framework[duckdb]>=9.0
